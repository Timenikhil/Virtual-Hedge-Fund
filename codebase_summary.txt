Entry points
------------
- vhf/execution/alpaca_trade_api.py

-----------------------

  - moonshot_orders(strategy, review_date, accounts)  – wraps `quantrocket moonshot orders`
  - moonshot_trade(strategy, review_date, accounts)   – wraps `quantrocket moonshot trade`
  - realtime_create_tick_db(), realtime_create_agg_db(), realtime_collect(),
    realtime_stop(), etc.        – realtime data collection commands

Live data streaming
-------------------
- vhf/execution/live_data.py

  - create_agg_db()             – create aggregated bar DB from tick data
  - start_collection(*codes)    – start streaming
  - stop_collection(*codes)     – stop streaming
  All wrap the QuantRocket CLI and raise RealtimeError on failure.

3. PORTFOLIO ALLOCATOR
================================================================================

Allocation Service (vhf/services/allocation_service.py)
---------------------------------------------------------
Primary function: allocate_portfolio(request: AllocationRequest) -> AllocationResult

Method              Behaviour
------------------+-----------------------------------------------------------------
equal_weight        1/n to each strategy; always deterministic
score_weighted      latest price of each strategy used as score signal;
                    falls back to equal_weight if all scores ≤ 0
ai_weighted         calls resolve_allocator_provider(), builds context (portfolio_id,
                    strategy list, current weights, per-strategy name/desc/category/
                    prices, optional caller-supplied ai_context), sends to provider
                    with timeout; non-strict mode falls back to equal_weight on error;
                    strict mode re-raises
manual              uses raw_weights from request or portfolio.weights;
                    falls back to equal_weight if none available

Weight helpers
  _validate_weight_vector() – checks shape, finiteness, non-negativity, sum > 0
  _normalize()              – divides by sum to produce probability vector
  record_allocation_snapshot() called on every result for audit trail

AI Provider resolution (vhf/ai/weight_allocator_provider.py)
--------------------------------------------------------------
WeightAllocatorProvider protocol: name, allocate(context, *, timeout_seconds)

Implementations
  DisabledWeightAllocatorProvider  – always raises
  LocalWeightAllocatorProvider     – dynamic import of vhf.ai.ai_weight_allocator,
                                     calls allocate_weights()
  RemoteWeightAllocatorProvider    – HTTP POST to AI_ALLOCATOR_URL with Bearer token
                                     (AI_ALLOCATOR_API_KEY)

resolve_allocator_provider(mode)
  auto  → tries local, falls back to remote if AI_ALLOCATOR_URL set, else disabled
  explicit mode → use directly

AI response parsing (_extract_ai_weights) accepts:
  list [w1, w2, ...]
  dict with "weights" / "target_weights" / "raw_weights" key
  dict with "allocations" map {"sid": weight}
  flat dict {"sid": weight}

Rebalance Engine (vhf/services/rebalance_engine.py)
----------------------------------------------------
Primary function: build_rebalance_plan(request: RebalanceRequest) -> RebalancePlan

Process:
  1. Calls allocate_portfolio() to compute target weights
  2. Normalises current_weights (from request or portfolio.weights) and target_weights
  3. For each strategy leg:
       delta = target – current
       if |delta| >= threshold: trade_weight = delta (buy / sell)
       if |delta| < threshold:  trade_weight = 0   (hold – avoids micro-trades)
  4. If apply=true AND rebalance_required:
       update_portfolio_weights() → triggers _sync_allocations_from_db()
  5. Records rebalance_run audit entry

Drift metrics: L1_drift = Σ|delta|,  max_abs_drift = max(|delta|)

Reconcile Service (vhf/services/reconcile_service.py)
------------------------------------------------------
Primary function: run_reconcile_job(job_id) -> ReconcileRunResult

Workflow:
  1. Load ReconcileJob from DB
  2. build_rebalance_plan() with job's method / threshold / AI params
  3. If execute_trades=true:
       Requires apply=true and mapped account
       Iterates non-hold legs only
         dry_run_trades=true  → generate_orders_csv()
         dry_run_trades=false → trade_strategy_to_alpaca()
       Collects StrategyTradeResult per leg; captures errors
  4. Status: "partial_error" | "dry_run" | plan status (applied/needs_rebalance/noop)
  5. update_reconcile_job_after_run() → persists status, error, next_run_at

Reconcile Scheduler (vhf/services/reconcile_scheduler.py)
----------------------------------------------------------
Class: ReconcileScheduler

  __init__(poll_interval_seconds, worker_id)
    Defaults: 86400 s poll, minimum 5 s, worker_id = "{hostname}:{pid}"

  start() / stop()         – manage background async task
  run_due_jobs_once()      – claim jobs → execute in thread → return results
  _run_loop()              – infinite async loop with stop event

Distributed lock:
  claim_due_reconcile_jobs() atomically sets LOCKED_AT=now, LOCKED_BY=worker_id
  for jobs where ENABLED=1, NEXT_RUN_AT <= now, and
  (LOCKED_AT IS NULL OR LOCKED_AT older than DEFAULT_RECONCILE_LOCK_TIMEOUT_SECONDS=3600 s)

Environment overrides:
  RECONCILE_SCHEDULER_ENABLED        (default: true)
  RECONCILE_SCHEDULER_POLL_SECONDS   (default: 86400)
  RECONCILE_SCHEDULER_WORKER_ID      (override worker identity)

Test pattern
------------
- Framework: unittest + unittest.mock
- All DB operations mocked at call site (no real DB access in unit tests)
- QuantRocket CLI and remote AI provider calls mocked
- Assertions target method call counts, arguments, and return values

What is tested
--------------
  All allocation methods (manual / equal_weight / score_weighted / ai_weighted)
  Weight validation and normalisation
  AI provider fallback (strict vs non-strict)
  Rebalance plan construction and threshold filtering
  Reconcile job execution lifecycle and state updates
  Distributed lock / claim semantics (scheduler)
  Strategy selection (topk / bottomk / prompt parser)

What is NOT tested
------------------
  Real DB persistence
  Real QuantRocket CLI calls
  Real HTTP remote AI provider calls
  Frontend / API integration
  End-to-end reconcile cycle with live trades
  Edge cases: malformed DB state, network timeouts, partial trade failures

END-TO-END FLOW SUMMARY
================================================================================

Allocation → Trade
  User → POST /api/v1/allocate-portfolio
       → allocate_portfolio() [fetch DB, apply method, normalise, record snapshot]
       → (optional) build_rebalance_plan() [threshold filter, apply weights]
       → (reconcile job) run_reconcile_job() [trade non-hold legs]
       → trade_strategy_to_alpaca() → QuantRocket Moonshot CLI → Alpaca blotter

Portfolio weights → QuantRocket
  update_portfolio_weights()
    → _sync_allocations_from_db()
    → update_account_allocations() [write QuantRocket allocations YAML]
    → QuantRocket reads YAML → Moonshot generates orders

Scheduler loop
  ReconcileScheduler._run_loop() [async, every POLL_SECONDS]
    → claim_due_reconcile_jobs(worker_id)  [atomic DB lock]
    → run_reconcile_job(job_id) per claimed job
        → build_rebalance_plan() → allocate_portfolio()
        → execute trades (if enabled)
        → update_reconcile_job_after_run()
